## Registers 
> A register is a **small amount of data storage** avilable to the CPU whose contents contents can be accessed more quickly than any other storage avilable. 

Regestires is divided to 4 categuries 
1. **Instruction Pointer (PC)** -> Used to trake the next instruction to execute
	- EIP
2. **Genral Register (GPRs)** -> used by the CPU during execution (talk about it in specific later)
	- EAX,EBX,ECX,EDX,EBP,ESP,ESI,EDI
3. **Status Flags (EFLAGS)** -> Used to make decisions based of the status it has (talk about it in specific later)
	- EFLAGS(32-bit), RFLAGS(64-bit)
4. **segment register**
	- CS,SS,DS,ES,FS,GS

#### x86 register conventions (theses are suggestion from intel to the compiler developers )

- **EAX** — Stores the **return values**
- **EBX** — Base pointer to the **data section**
- **ECX** — **Counter** for string and loop operations.
- **EDX** — **I/O** pointer.

- **ESI** —  **Source** pointer for string operations
- **EDI** — **Destination** pointer for string operations

- **ESP** — **Stack** pointer
- **EBP** — **Stack** frame **base** pointer

#### Difference between 64-bits & 32-bits Assembly 
1. Address Space

2. Function Prologue

	The 32-bit side doesn't open with a plain `push ebp; mov ebp,esp`. It starts with `lea ecx,[esp+0x4]`, and `esp,0xfffffff0`, `push DWORD PTR [ecx-0x4]` — that's the compiler _realigning_ the stack to a 16-byte boundary before setting up the frame, using ECX to stash the original return-address-adjusted ESP so it can be restored later. Only after that does the classic `push ebp; mov ebp,esp` happen.

	The 64-bit side has none of this but as written it looks like "64-bit is simpler," when the actual reason is that this particular 32-bit build needed stack realignment (likely for the `printf`/`puts` calls) and the 64-bit build didn't need the same trick. Worth a sentence clarifying that, or better, compiling both with `-fno-stack-protector` and no extra alignment pressure so the comparison is apples-to-apples.

## Common Assembly Instructions

### Data Moving 
We use these to copy data from place to another (we will talk about these places)
#### MOV 
Used to Copy data from one location to another , it has more than form 
![](assets/img/posts/X86-64 for RE/6.png)

#### From memory to a register
	Memory → General-purpose register** : `mov eax, [ebx]` — loads the 4 bytes at the address in EBX into EAX
	Memory → Segment register** : `mov ds, [ebx]` — loads a 16-bit value from memory into DS

#### From a register to memory

	General-purpose register → Memory location : `mov [ebx], eax` — stores EAX's value at the address in EBX
	Segment register → Memory location : `mov [ebx], ds` — stores DS's value into memory

#### Between registers
	General-purpose → General-purpose: `mov eax, ebx` — copies EBX into EAX
	General-purpose → Segment register: `mov ds, ax` — loads DS from AX (only 16-bit GPRs can feed a segment register)
	Segment → General-purpose register: `mov ax, ds` — reads DS into AX
	General-purpose → Control register: `mov cr0, eax` — writes EAX into CR0 (privileged, ring 0 only)
	Control register → General-purpose: `mov eax, cr0` — reads CR0 into EAX
	General-purpose → Debug register: `mov dr0, eax` — writes EAX into DR0 (also privileged)
	Debug register → General-purpose: `mov eax, dr0` — reads DR0 into EAX

#### Immediate data to a register
	Immediate → General-purpose register: `mov eax, 0x5` — loads the literal value 5 into EAX
#### Immediate data to memory
	Immediate → Memory location: `mov dword [ebx], 0x5` — writes the literal value 5 to the memory address in EBX (size specifier needed since there's no register to infer width from)
